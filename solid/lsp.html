L — Liskov Substitution Principle

لو عندك Parent وChild، المفروض تقدر تستخدم الـChild مكان الـParent من غير ما البرنامج يتفاجئ بسلوك غلط.

افتكرها

السؤال الذهبي: لو استبدلت الأب بالابن، هل كل العمليات المتوقعة من الأب لسه منطقية وشغّالة؟

1المثال الكلاسيكي

class Bird
{
    public function fly()
    {
        // fly
    }
}

class Penguin extends Bird
{
    public function fly()
    {
        throw new Exception('I cannot fly');
    }
}

البطريق طائر فعلًا، لكنه مش بيطير. الأب بيقول إن كل Bird عنده fly()، والابن مش قادر يحافظ على الوعد ده.

المشكلة العملية
function releaseBirds(array $birds): void
{
    foreach ($birds as $bird) {
        $bird->fly();      // بيقع لما يوصل للبطريق
    }
}

الدالة دي مكتوبة صح حسب الـcontract المعلن. اللي كسرها هو الابن اللي وعد ومنفّذش.

2شكل أفضل

interface Bird
{
    public function eat(): void;
}

interface FlyingBird extends Bird
{
    public function fly(): void;
}

class Sparrow implements FlyingBird
{
    public function eat(): void { }
    public function fly(): void { }
}

class Penguin implements Bird
{
    public function eat(): void { }
    // Penguin doesn't fly — ومحدش بيتوقع منه كده
}

دلوقتي النوع نفسه بيقول الحقيقة. الدالة اللي محتاجة طيران بتطلب FlyingBird، والبطريق مش هيعدّي أصلًا.

3LSP أعمق من الـmethod signatures

الابن ممكن ينفّذ كل الـmethods ويفضل كاسر الـLSP. الأشكال المشهورة:

الكسرالشكل
رمي exception جديدالأب مبيرميش، والابن بيرمي — والـcaller مش متوقع
تشديد الشروط (preconditions)الأب بيقبل أي رقم، والابن بيقبل الموجب بس
تخفيف الوعود (postconditions)الأب بيضمن ترتيب النتيجة، والابن مش بيضمن
تغيير المعنىsave() في الأب بيحفظ فورًا، وفي الابن بيحطها في queue
method فاضيةالابن بيعمل override بـreturn; عشان يتجاهل السلوك
المثال الأشهر: Square extends Rectangle
class Rectangle
{
    public function setWidth(int $w): void  { $this->w = $w; }
    public function setHeight(int $h): void { $this->h = $h; }
    public function area(): int { return $this->w * $this->h; }
}

class Square extends Rectangle
{
    public function setWidth(int $w): void
    {
        $this->w = $w;
        $this->h = $w;      // المربع لازم يفضل مربع
    }
}

// كود متوقّع سلوك المستطيل:
$r->setWidth(5);
$r->setHeight(4);
assert($r->area() === 20);    // بتقع مع المربع: 16

رياضيًا المربع نوع من المستطيل. لكن سلوكيًا مش كده — لأن المستطيل بيوعد إن العرض والطول مستقلين. الـis-a بتاعة الـOOP عن السلوك، مش عن التصنيف.

4العلامات التحذيرية

  • method في الابن بترمي NotSupportedException.
  • method في الابن جسمها فاضي (بتتجاهل السلوك).
  • الـcaller بيعمل if ($obj instanceof X) عشان يتعامل مع نوع معين بشكل خاص.
  • تعليق في الأب بيقول «الأبناء ممكن يتجاهلوا الـmethod دي».

العلامة رقم 3 بالذات مهمة: لو الـcaller محتاج يعرف النوع الحقيقي، فالـabstraction فشلت.
