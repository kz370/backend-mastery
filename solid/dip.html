D — Dependency Inversion Principle

الـBusiness Logic ما يعتمدش مباشرة على تفاصيل قابلة للتغيير؛ يعتمد على Abstraction.

افتكرها

السؤال الذهبي: لو غيّرت قاعدة البيانات، هل لازم أعدّل الـService نفسه؟ وهل أقدر أحقن FakeDatabase في الاختبار؟

1مثال فيه مشكلة

class MySQLDatabase
{
    public function save($data)
    {
        // save
    }
}

class UserService
{
    private MySQLDatabase $db;

    public function __construct()
    {
        $this->db = new MySQLDatabase();
    }
}

الـUserService مربوط مباشرة بـMySQLDatabase. لو غيّرنا لـPostgreSQL، لازم نعدّل الـService — وهو أصلًا مالوش دعوة بنوع قاعدة البيانات.

2شكل أفضل

interface Database
{
    public function save($data);
}

class MySQLDatabase implements Database
{
    public function save($data)
    {
        // save to MySQL
    }
}

class UserService
{
    public function __construct(
        private Database $db
    ) {}
}

دلوقتي الـUserService مش فارق معاه قاعدة البيانات إيه. ممكن نديه MySQL أو PostgreSQL أو FakeDatabase للاختبار.

3«Inversion» يعني إيه بالظبط؟

الاسم مش عشوائي — فيه قلب حقيقي في اتجاه الاعتماد:

✕ الاتجاه الطبيعي
UserService (high level) ↓ يعتمد على MySQLDatabase (low level detail)
✓ بعد القلب
UserService (high level) ↓ يعتمد على Database (interface) ↑ ينفّذه MySQLDatabase (detail)

لاحظ السهم اللي اتقلب: قبل كده الـservice كان بيعتمد على التفصيلة. دلوقتي التفصيلة هي اللي بتعتمد على الـabstraction.

النقطة الأهم

الـDatabase interface بيتحدد شكله حسب احتياج الـUserService، مش حسب قدرات MySQL. يعني الطبقة العليا هي اللي بتفرض شكل العقد — وده جوهر الـinversion. عشان كده في الـarchitecture النضيفة، الـinterface بيعيش مع الـdomain مش مع الـinfrastructure.

4DIP و DI — مش نفس الحاجة

DIP (المبدأ)DI (التقنية)
إيه هياعتمد على abstraction مش على تفاصيلمرّر الـdependency من بره
السؤالمعتمد على إيه؟الـdependency بتوصل إزاي؟
ممكن تعملها من غير التانية؟آهآه
// DI من غير DIP — بحقن، لكن على implementation مباشرة
public function __construct(private MySQLDatabase $db) {}

// DIP من غير DI — معتمد على abstraction، لكن بعمل new بنفسي
public function __construct()
{
    $this->db = new MySQLDatabase();   // النوع Database، لكن أنا اللي بنيته
}

// الاتنين مع بعض ✓
public function __construct(private Database $db) {}

5علامات كسر الـDIP

  • new لـinfrastructure جوه business logic (new PDO, new Client).
  • الـdomain layer بيستورد من الـvendor أو الـframework.
  • مش قادر تكتب test من غير ما تشغّل database أو تتصل بالنت.
  • اسم مزوّد خارجي ظاهر في اسم method أو parameter في الـbusiness logic.
مش كل حاجة تستاهل abstraction

ما تعملش interface لـDateTime أو Str أو أي حاجة من الـstandard library مستقرة. الـDIP بتستهدف التفاصيل المتغيّرة والخارجية: قواعد بيانات، APIs، بريد، تخزين ملفات، بوابات دفع.
