I — Interface Segregation Principle

ما تعملش Interface ضخمة وتجبر الكلاسات تنفّذ حاجات هي مش محتاجاها.

افتكرها

السؤال الذهبي: هل الـclass مضطرة تنفّذ methods هي مش بتستخدمها، بس لأنها طبّقت Interface؟

1مثال فيه مشكلة

interface Worker
{
    public function work();
    public function eat();
}

class Robot implements Worker
{
    public function work()
    {
        // work
    }

    public function eat()
    {
        // Robot does not eat!
    }
}

الـRobot محتاج work() بس، لكن الـinterface أجبره ينفّذ eat() كمان — فبقى عنده method فاضية أو بترمي exception.

لاحظ الرابط بالـLSP

الـmethod الفاضية دي مش مجرد كود زيادة — دي كسر للـLSP كمان. أي كود بيتعامل مع Worker ويستدعي eat() هيتصرف غلط مع الروبوت. المبدآن بيتقابلوا هنا.

2شكل أفضل

interface Workable
{
    public function work();
}

interface Eatable
{
    public function eat();
}

class Human implements Workable, Eatable
{
    public function work() { }
    public function eat()  { }
}

class Robot implements Workable
{
    public function work() { }
}

الـinterfaces الصغيرة أسهل في الفهم والتنفيذ والاختبار. وكل class بتاخد اللي يخصها بس.

3الفايدة الحقيقية: تقليل أسباب التغيير

الـISP مش بس عن الـmethods الفاضية. الفايدة الأعمق:

interface ضخم فيه 12 method ↓ أي تعديل فيه بيجبر كل الـimplementations تتعدّل ↓ حتى اللي مش مهتمة بالـmethod اللي اتغيرت

يعني الـinterface الضخم بيخلي كل الـimplementations مربوطة ببعض بشكل غير مباشر — تعديل عشان class واحدة بيلمس كل الباقيين.

4Role interfaces

طريقة تفكير عملية: بدل ما تعمل interface يوصف الـclass، اعمله يوصف الدور:

✕ interface بيوصف الـclass
interface UserRepositoryInterface
{
    public function find($id);
    public function all();
    public function create(array $data);
    public function update($id, array $data);
    public function delete($id);
    public function paginate($perPage);
    public function search($term);
    // ...12 method
}
✓ interfaces بتوصف الأدوار
interface FindsUsers
{
    public function find(int $id): ?User;
}

interface StoresUsers
{
    public function save(User $user): void;
}

دلوقتي الـclass اللي محتاجة تقرأ بس بتعتمد على FindsUsers — فالـtest بتاعها بيحتاج mock لـmethod واحدة بدل 12.

علامة عملية

لو بتكتب test ولقيت نفسك بتعمل mock لـ8 methods عشان تستخدم واحدة، فالـinterface ده أكبر من اللازم.

5خلي بالك من المبالغة

interface لكل method؟

لأ. لو تلات methods دايمًا بتتنادي مع بعض ومن نفس النوع من الـclients، فهما ينتموا لنفس الـinterface. الـISP عن الاستخدام الفعلي مش عن العدد. السؤال: هل فيه client حقيقي محتاج جزء بس من الـinterface؟
