Order.php

<?php

class Order
{
    public $items = [];
    public $customer;
    public $status = 'pending';
    public $paymentMethod = '';
    public $discountCode = '';
    public $discountPercent = 0;

    public function __construct($customer)
    {
        $this->customer = $customer;
    }

    public function addItem($product, $quantity)
    {
        $this->items[] = [
            'product'  => $product,
            'quantity' => $quantity,
        ];
    }

    public function applyDiscount($code)
    {
        if ($code === 'SAVE10') {
            $this->discountCode = $code;
            $this->discountPercent = 10;
        } elseif ($code === 'SAVE25') {
            $this->discountCode = $code;
            $this->discountPercent = 25;
        }
    }

    public function calculateTotal()
    {
        $total = 0;

        foreach ($this->items as $item) {
            $total += $item['product']->price * $item['quantity'];
        }

        return $total;
    }

    public function processPayment()
    {
        $total = $this->calculateTotal();

        if ($this->discountPercent > 0) {
            $total = $total - ($total * $this->discountPercent / 100);
        }

        if ($this->paymentMethod === 'creditcard') {
            echo "Charging credit card of {$this->customer->name}...\n";
            $this->status = 'paid';
            return true;
        } elseif ($this->paymentMethod === 'paypal') {
            echo "Redirecting {$this->customer->name} to PayPal...\n";
            $this->status = 'paid';
            return true;
        } elseif ($this->paymentMethod === 'wallet') {
            if ($this->customer->walletBalance >= $total) {
                $this->customer->walletBalance -= $total;
                $this->status = 'paid';
                return true;
            }

            echo "Wallet has insufficient funds!\n";
            return false;
        }

        echo "Unknown payment method: {$this->paymentMethod}\n";
        return false;
    }

    public function sendConfirmationEmail()
    {
        $total = $this->calculateTotal();

        if ($this->discountPercent > 0) {
            $total = $total - ($total * $this->discountPercent / 100);
        }

        $body = "Hi {$this->customer->name}, thanks for your order! "
              . "Total: \${$total}. Status: {$this->status}.";

        (new EmailSender())->send($this->customer->email, 'Order confirmation', $body);
    }

    public function saveToFile()
    {
        $line = date('Y-m-d H:i:s')
              . " | customer: {$this->customer->name}"
              . " | status: {$this->status}"
              . " | items: " . count($this->items) . "\n";

        file_put_contents(__DIR__ . '/orders.txt', $line, FILE_APPEND);
    }
}

class VipOrder extends Order
{
    public function calculateTotal()
    {
        $total = 0;

        foreach ($this->items as $item) {
            $total += $item['product']->price * $item['quantity'];
        }

        return $total * 0.8;   // VIP members always pay 20% less
    }
}

3التحديات العشرة

امشِ فيهم بالترتيب تقريبًا. ما تعملش refactor لكل حاجة مرة واحدة — حل، شغّل، لاحظ.

1. اختبار العبث (The tampering test)

المطلوب

في index.php، بعد ما Order 1 يتنفّذ، ضيف:

$order1->status = 'shipped';
$keyboard->price = 0.01;

شغّل — مفيش حاجة بتمنعك. دلوقتي اعمل قائمة بكل property في المشروع يقدر كود من بره يغيّرها، وعلّم اللي مفروض محدش يلمسها مباشرة.

المفهوم: Encapsulation

2. مطاردة الفلوس (The money hunt)

المطلوب

دوّر على السطر اللي Order بيغيّر فيه رصيد Sara. واسأل نفسك:

  1. فين السطر اللي بيغيّر الـbalance؟
  2. مين اللي بيعمل التغيير ده حاليًا؟
  3. هل دي مسؤوليته ولا مسؤولية الـWallet؟ وليه؟
  4. إيه المشكلة لو classes كتير تقدر تعدّل الـbalance مباشرة؟

مش مطلوب تصلّح الكود دلوقتي — المطلوب تكتشف المشكلة وتشرح شايفها إزاي.

المفهوم: Responsibility

3. إنترفيو للـOrder

المطلوب

اكتب كل شغلانة مستقلة بيعملها Order::processPayment() وجيرانها. أنهي شغلانة فيهم بتحس إنها غلط في class اسمها «Order»؟ وكل شغلانة مكانها الطبيعي فين؟

المفهوم: SRP

4. مطاردة التكرار

المطلوب

دوّر على كل مكان بيتحسب فيه «الإجمالي بعد الخصم»، وكل مكان فيه الـloop بتاعة جمع الـitems. وبعدين:

خلّي SAVE10 بـ15% بدل 10%، وضيف كوبون جديد WELCOME5 بـ5%. كام مكان اضطريت تعدّل فيه؟ والرقم ده بيقولك إيه عن الـbugs الجاية؟

المفهوم: DRY

5. إضافة طريقة دفع — بالطريقة المؤلمة

المطلوب

ضيف دعم crypto بتعديل الكود الحالي. عدّ كل سطر لمسته جوه Order.php. دلوقتي تخيّل 10 طرق دفع — اوصف شكل processPayment() ساعتها.

المفهوم: Coupling · OCP

6. رسم العقد

المطلوب

على ورقة (أو في تعليقات)، عرّف الـmethod signature اللي هيشترك فيها الكارت والـPayPal والمحفظة لو بقوا objects. وبعدين جاوب: لو الـOrder ماسك واحد من الـobjects دي، هل لسه محتاج if/elseif عشان يعرف نوعه قبل ما ينادي عليه؟

المفهوم: Interface · Polymorphism · Strategy

7. تجربة الـVIP

المطلوب

اعمل VipOrder لخالد، نادِ applyDiscount('SAVE10')، ضيف كيبورد واحد، وادفع بالكارت. احسب المبلغ المتوقع قبل ما تشغّل، وبعدين قارن بالواقع.

إيه اللي حصل؟ وأخيرًا احكم على التصميم: هل الـVipOrder فعلًا نوع مختلف من الطلب — ولا «الـVIP» حاجة تانية خالص في الـdomain لابسة زي الطلب؟

المفهوم: Inheritance · LSP

8. الـdependency المخفية

المطلوب

دوّر على كل new مستخدمة جوه methods الـOrder. ليه بناء الـEmailSender جواه ممكن يكون مزعج — في الـtesting مثلًا، أو لو بكرة التأكيدات هتتبعت SMS؟ ارسم (من غير تنفيذ) إزاي الـsender ممكن ييجي للـorder من بره.

المفهوم: Dependency Injection

9. حواجز الأمان

المطلوب

نادِ $order->applyDiscount('HELLO') — بتعدّي في صمت. وجرّب addItem($mouse, -5) وشوف الإجمالي بقى كام.

إيه المفروض يحصل مع المدخلات الغلط؟ وفين المفروض القواعد دي تعيش عشان الـcallers ما يقدروش يعدّوا من حواليها؟

المفهوم: Invariants

10. المخطط (Blueprint)

المطلوب

من غير ما تنفّذ حاجة: ارسم البنية بعد الـrefactoring. أنهي classes/interfaces هتوجد، مين بيمسك مرجع لمين، وإيه اللي public وإيه اللي private. وعلّم كل قرار بالمفهوم اللي بيعبّر عنه.

ده أهم تحدي فيهم كلهم — لأنه بيجمّع كل القرارات في تصميم واحد.
