DRY — Don't Repeat Yourself

ما تكررش نفس الـlogic في أماكن مختلفة. لكن الأهم: DRY عن تكرار المعرفة، مش تكرار السطور.

افتكرها

نفس الـrule ما تتكتبش وتتكرر في كل حتة. لو القاعدة اتغيّرت، المفروض تعدّل في مكان واحد.

1المشكلة

في المشروع، حساب «الإجمالي بعد الخصم» موجود في مكانين على الأقل:

public function processPayment()
{
    $total = $this->calculateTotal();

    if ($this->discountPercent > 0) {
        $total = $total - ($total * $this->discountPercent / 100);   // ← 1
    }
    // ...
}

public function sendConfirmationEmail()
{
    $total = $this->calculateTotal();

    if ($this->discountPercent > 0) {
        $total = $total - ($total * $this->discountPercent / 100);   // ← 2
    }
    // ...
}
جرّب بنفسك

خلّي SAVE10 بـ15% بدل 10%، وضيف كوبون جديد WELCOME5 بـ5%.

كام مكان اضطريت تعدّل فيه؟ والعدد ده بيقولك إيه عن احتمالية الـbugs في المستقبل؟

والأخطر: لو نسيت مكان واحد، هيحصل إن العميل يدفع مبلغ ويتبعتله إيميل بمبلغ تاني. الـbug ده مش هيرمي exception — هيفضل شغال في صمت لحد ما عميل يشتكي.

2الحل

class Order
{
    public function subtotal(): Money
    {
        return array_reduce(
            $this->items,
            fn (Money $sum, OrderItem $item) => $sum->plus($item->lineTotal()),
            Money::zero()
        );
    }

    public function total(): Money
    {
        return $this->coupon
            ? $this->coupon->applyTo($this->subtotal())
            : $this->subtotal();
    }
}

// وكل مكان محتاج الإجمالي:
$order->total();

دلوقتي فيه مصدر واحد للحقيقة (single source of truth). لو قاعدة الخصم اتغيّرت، بتعدّل في Coupon والكل بياخد التغيير.

3أهم نقطة: DRY عن المعرفة مش عن الحروف

مش كل كود متشابه = تكرار

خد المثال ده — كودين متطابقين تقريبًا:

✕ حساب ضريبة المبيعات
$tax = $amount * 0.14;
✓ حساب عمولة المندوب
$commission = $amount * 0.14;

لو عملتلهم دالة مشتركة calculate14Percent()، فأنت ربطت حاجتين مالهمش علاقة ببعض. أول ما الضريبة تتغير لـ15%، العمولة هتتغير معاها غصب عنك — وده bug.

القاعدة: الكودين دول متشابهين بالصدفة (coincidental duplication)، مش تكرار حقيقي. التكرار الحقيقي هو لما يكون في قاعدة واحدة متكتوبة في أكتر من مكان.

تكرار حقيقي (اتخلص منه)تشابه بالصدفة (سيبه)
نفس قاعدة الخصم في 3 methodsدالتين بيضربوا في نفس الرقم لسببين مختلفين
نفس الـvalidation في Controller وModelشكل مشابه لـloop على arrays مختلفة
نفس منطق حساب الشحن في مكانينتلات classes ليهم نفس الـconstructor shape

4الوجه التاني: WET و over-DRY

زي كل مبدأ، فيه مبالغة في الاتجاهين:

المشكلةالشكلالنتيجة
WET (تكرار زيادة)نفس القاعدة في 5 أماكنتعدّل 5 مرات، وتنسى واحدة → bug صامت
Over-DRYabstraction مشتركة بتخدم 3 حالات مختلفةدالة فيها 6 flags وifات، وتغيير لحالة بيكسر التانية
قاعدة عملية (rule of three)

أول تكرار: سيبه. تاني تكرار: خلي بالك. تالت تكرار: دلوقتي عندك دليل كافي إن دي قاعدة حقيقية — اعملها abstraction. الاستعجال في الـabstraction بيوصل لـcoupling أسوأ من التكرار نفسه.

5مستويات التكرار

التكرار مش بس في الكود — دي أشكاله في مشروع حقيقي:

  • Logic — نفس القاعدة الحسابية أو الشرط في أكتر من مكان.
  • Validation — نفس الشروط في الـRequest والـModel والـController.
  • Magic values — 'paid' مكتوبة نصًّا في 12 ملف (استخدم enum أو constant).
  • Structure — نفس شكل الـquery متكرر (استخدم scope أو repository method).
  • Knowledge — قاعدة عمل موجودة في الكود وفي الـDB constraint وفي الـfrontend، وكل واحدة ليها نسختها.

6Interview

سؤال بيتسأل كتير: هل DRY دايمًا صح؟

«DRY عن تكرار المعرفة مش تكرار السطور. لو نفس القاعدة موجودة في كذا مكان، ده تكرار حقيقي لازم يتجمّع، لأن أول ما تتغير هنسى مكان. لكن لو كودين شكلهم واحد لأسباب مختلفة، توحيدهم بيخلق ارتباط مضر — أول ما سبب يتغير، التاني يتكسر معاه. فأنا بسأل: هل ده نفس القرار، ولا مجرد نفس الشكل؟»

الخلاصة

لو غيّرت قاعدة واحدة واضطريت تفتح أكتر من ملف — ده تكرار.
