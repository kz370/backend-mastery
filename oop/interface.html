Interface — العقد (Contract)

الـInterface بيقول: أي class هتشتغل كـPaymentMethod لازم توفّر الـmethods دي. وده الفرق بين إنك تتعامل مع «إيه» بدل «إزاي».

افتكرها

Interface = Contract بيحدد الشكل اللي الـimplementations لازم تلتزم بيه. Abstraction = إني أتعامل مع «إيه» مش «إزاي».

1الفكرة

interface PaymentMethod
{
    public function pay(Money $amount): PaymentResult;
}

class CreditCardPayment implements PaymentMethod
{
    public function pay(Money $amount): PaymentResult
    {
        // credit card logic
    }
}

class PayPalPayment implements PaymentMethod
{
    public function pay(Money $amount): PaymentResult
    {
        // PayPal logic
    }
}

الـOrder يتعامل مع PaymentMethod، مش مع CreditCardPayment ولا PayPalPayment.

Order ↓ يعرف PaymentMethod ← الـcontract (ثابت) ↑ بينفّذوه CreditCard · PayPal · Wallet ← التفاصيل (بتتغير)

2ليه ده مفيد؟

المكسبالتفصيل
إضافة بدون تعديلتضيف FawryPayment من غير ما تفتح Order خالص.
Testingتعمل FakePayment بترجّع نتيجة ثابتة، وتختبر الـOrder من غير شبكة.
توثيق ذاتيالـinterface بيقولك بالظبط إيه المطلوب من أي طريقة دفع — من غير ما تقرا أي implementation.
حدود واضحةبيرسم خط بين «اللي مشروعي محتاجه» و«اللي المزوّد بيقدّمه».

3Interface مش مجرد keyword

الفخ: interface بيعكس implementation واحدة
// interface اتعمل بعد ما Stripe اتكتبت، فطلع على مقاسها
interface PaymentGateway
{
    public function createStripeToken(array $card): string;
    public function chargeWithStripeToken(string $token, int $cents): array;
    public function getStripeCustomerId(): ?string;
}

الـinterface ده اسمه عام، لكن شكله كله Stripe. أول ما تيجي تعمل FawryGateway هتلاقي نفسك بترجّع null وترمي exceptions في نص الـmethods.

القاعدة: الـinterface لازم يتصاغ بلغة اللي مشروعك محتاجه، مش بلغة أول مزوّد اشتغلت معاه. لو مشروعك محتاج «اخصم مبلغ وقولي نجحت ولا لأ»، فالـinterface هو بالظبط:

interface PaymentGateway
{
    public function charge(Money $amount, PaymentDetails $details): PaymentResult;
}

4Interface vs Abstract Class

InterfaceAbstract Class
بيقول إيه«لازم تعرف تعمل الحاجات دي»«إنت نوع مني، وورثت شغل جاهز»
فيه كود؟لأ (بس signatures)آه، ممكن يبقى فيه methods جاهزة
كام واحد ممكن تعمل implement؟أكتر من واحدواحد بس (single inheritance)
العلاقةcan-do — قدرةis-a — نوع
امتىلما تحدد قدرة ممكن أنواع مختلفة تمامًا يشتركوا فيهالما يكون فيه كود مشترك حقيقي وعلاقة نوع

مثال يوضح الفرق: Serializable قدرة ممكن تبقى في User وInvoice وReport — دول مالهمش أي علاقة ببعض، فده interface. لكن PdfReport extends Report علاقة نوع، وفيها كود مشترك، فده abstract class.

5الـAbstraction بمعناها الأوسع

الـinterface مجرد أداة للـabstraction، مش هي الـabstraction نفسها. الـabstraction هي إنك تخفي التفاصيل اللي مش مهمة للـcaller:

  • $order->total() — أنت مش عارف هي بتلف على الـitems ولا بتقرا cache، ومش محتاج تعرف.
  • $wallet->debit($m) — بتخفي كل قواعد الفلوس ورا اسم واحد.
  • Money::fromEgp(50) — بتخفي إن الرقم متخزّن كـcents جوه.
علامة abstraction كويسة

الـcaller يقدر يستخدمها صح من غير ما يقرا الكود اللي جواها. لو محتاج يبص جوه عشان يفهم يستخدمها إزاي، فالـabstraction فاشلة.

6Interview

سؤال: Interface vs Abstract Class?

«الـinterface بيحدد قدرة — أي class تلتزم بيه لازم توفّر الـmethods دي، ومش لازم يكون بينهم أي علاقة نوع. الـabstract class بتقول علاقة نوع وبتوفّر كود مشترك للأبناء. عمليًا: لو محتاج أعرّف عقد بس، بستخدم interface. لو فيه سلوك مشترك حقيقي والعلاقة is-a، بستخدم abstract class. وفي PHP أقدر أعمل implement لأكتر من interface، لكن extend لواحد بس.»

الخلاصة

الـOrder يعرف إيه اللي محتاجه، لكن مش محتاج يعرف التنفيذ حصل إزاي.
