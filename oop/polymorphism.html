Polymorphism — نفس النداء، سلوك مختلف

نفس الـcontract، implementations مختلفة، وكل object ينفّذ الـbehavior بطريقته — من غير ما الـcaller يسأل «إنت مين؟».

افتكرها

لو لقيت نفسك بتسأل الـobject «إنت نوع إيه؟» عشان تقرر تعمل إيه — غالبًا محتاج polymorphism.

1المشكلة: سلسلة الـif

public function pay(string $type, float $amount)
{
    if ($type === 'credit_card') {
        // credit card logic
    } elseif ($type === 'paypal') {
        // PayPal logic
    } elseif ($type === 'wallet') {
        // wallet logic
    }
}

المشكلة مش في الـif نفسها. المشكلة إن نفس السلسلة دي بتتكرر في كل مكان محتاج يتصرف حسب النوع:

pay() → if credit_card / paypal / wallet refund() → if credit_card / paypal / wallet generateReceipt()→ if credit_card / paypal / wallet canRetry() → if credit_card / paypal / wallet
لما تضيف نوع جديد

لازم تفتكر كل الأماكن دي وتضيف فيها. ولو نسيت واحدة، الكود مش هيرمي error — هيسقط في الـelse ويتصرف غلط في صمت.

2الحل

interface PaymentMethod
{
    public function pay(Money $amount): PaymentResult;
    public function refund(Money $amount): void;
    public function canRetry(): bool;
}

// الـcaller:
$this->paymentMethod->pay($amount);

سطر واحد. الـobject اللي موجود فعليًا هو اللي بيقرر السلوك.

$method->pay($amount) ↓ اللي بيتنفّذ فعليًا: ↓ CreditCardPayment::pay() لو الـobject credit card PayPalPayment::pay() لو الـobject paypal WalletPayment::pay() لو الـobject wallet

وأهم مكسب: لما تضيف FawryPayment، الـcompiler/الـinterface بيجبرك تنفّذ كل الـmethods المطلوبة. استحالة تنسى واحدة.

3الأشكال المختلفة للـPolymorphism

النوعإيه هومثال
Subtype (الأشهر)أنواع مختلفة بتحقق نفس الـinterfacePaymentMethod وتنفيذاته
Overridingالابن بيغيّر سلوك method ورثهاVipOrder::calculateTotal()
Parametric / Genericsنفس الكود بيشتغل على أنواع مختلفةCollection<T>
Ad-hoc / Overloadingنفس الاسم بـsignatures مختلفةمش موجود في PHP بشكل مباشر

في الشغل اليومي، لما حد يقول «polymorphism» غالبًا بيقصد النوع الأول.

4امتى الـif تكون أحسن؟

مش كل if لازم تتحوّل لـpolymorphism

الـpolymorphism تكلفتها: interface + class لكل نوع + مكان بيقرر أنهي object يتعمل. التكلفة دي تستحق لما:

  • الأنواع أكتر من 2–3.
  • نفس التفرقة بتتكرر في أكتر من method.
  • متوقّع تضيف أنواع جديدة.

لكن لو عندك:

$label = $isActive ? 'مفعّل' : 'موقوف';

ما تعملش ActiveLabelStrategy وInactiveLabelStrategy. الـif هنا أوضح وأصدق.

5العلاقة بالـPatterns

الـpolymorphism هي الآلية اللي شغّالة تحت معظم الـdesign patterns:

Patternبيستخدم الـpolymorphism إزاي
Strategyنفس العملية، implementations مختلفة
Stateنفس العملية، لكن السلوك حسب الحالة الحالية
Decoratorنفس الـinterface، بس بيلف حوالين object تاني
Observerكل observer بينفّذ رد فعله بطريقته

عشان كده فهم الـpolymorphism كويس بيخلّي الـpatterns تبان بديهية بدل ما تبقى أسماء محفوظة.

6Interview

سؤال: Polymorphism بتحل إيه بالظبط؟

«بتشيل من الـcaller مسؤولية إنه يعرف الأنواع. بدل سلسلة if بتتكرر في كل method، بيبقى فيه interface واحد وكل نوع ينفّذه بطريقته، والـcaller ينادي نفس الـmethod. وأهم مكسب عملي إن إضافة نوع جديد بتبقى class جديدة بس — والـinterface بيجبرني أنفّذ كل المطلوب، فمستحيل أنسى مكان.»
