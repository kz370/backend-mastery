Builder

بنستخدمه لما بناء الـobject نفسه يكون معقد، وفيه أجزاء كتير بعضها مطلوب وبعضها اختياري.

افتكرها

Builder = «ابنيلي الـobject ده» — مش «نفّذ العملية دي».

1المشكلة

لو الـobject بسيط، مش محتاج Builder خالص:

$user = new User($name, $email, $password);

لكن لما الـconstructor يبقى فيه parameters كتير، الكود بيبقى صعب القراءة:

$order = new Order($customer, $items, $address, 'card', 'SUMMER20', null, true, false);
//                                                          ↑ إيه دي؟  ↑ وده؟
المشكلة
  • مش واضح كل parameter بيعمل إيه من غير ما تفتح الـconstructor.
  • الـparameters الاختيارية بتخليك تمرّر null كتير.
  • أي إعادة ترتيب في الـconstructor بتكسر كل الـcallers.

2الحل

class OrderBuilder
{
    private ?Customer $customer = null;
    private array $items = [];
    private ?string $address = null;
    private ?string $paymentMethod = null;
    private ?string $coupon = null;

    public function customer(Customer $customer): self
    {
        $this->customer = $customer;
        return $this;
    }

    public function items(array $items): self
    {
        $this->items = $items;
        return $this;
    }

    public function address(string $address): self
    {
        $this->address = $address;
        return $this;
    }

    public function paymentMethod(string $method): self
    {
        $this->paymentMethod = $method;
        return $this;
    }

    public function coupon(string $coupon): self
    {
        $this->coupon = $coupon;
        return $this;
    }

    public function build(): Order
    {
        if ($this->customer === null) {
            throw new LogicException('Order requires a customer.');
        }

        return new Order(
            $this->customer,
            $this->items,
            $this->address,
            $this->paymentMethod,
            $this->coupon
        );
    }
}

الاستخدام

$order = (new OrderBuilder())
    ->customer($customer)
    ->items($items)
    ->address($address)
    ->paymentMethod('card')
    ->coupon('SUMMER20')
    ->build();

كل سطر بيقول إيه اللي بيتحط بالظبط. والـreturn $this هي اللي بتخلي الـfluent chaining ممكن.

نقطة مهمة

build() هي اللحظة اللي الـobject النهائي بيتعمل فيها — وهي المكان الطبيعي للتحقق من إن كل المطلوب موجود.

سؤال بيتسأل كتير

«عندي CreateOrderAction بتعمل validation وتحسب خصم وتنشئ Order وتبعت notification. هي Builder؟»

لأ. دي Action بتنفّذ عملية بيزنس كاملة. كونها بتنشئ وترجّع Order مش بيخليها Builder. ممكن تستخدم Builder جواها لو بناء الـOrder نفسه معقد — لكن الاتنين دورين مختلفين.

4امتى ما تستخدموش

لو الـobject بسيط، الـBuilder بيبقى overengineering: classes وكود زيادة من غير قيمة حقيقية. الـconstructor العادي أوضح.

الميزةالعيب
Construction أوضح ومقسّم لخطواتclasses وكود زيادة
تتعامل مع optional parts بسهولةطبقة زيادة بين الـcaller والـobject
مكان طبيعي للتحقق النهائيلازم التعقيد يبرّرها

5في Laravel

الـQuery Builder هو أشهر مثال: User::where(...)->orderBy(...)->limit(10)->get(). كل method بترجّع $this، وget() هي الـbuild().

6Interview

ليه Builder بدل الـconstructor العادي؟

«لو بناء الـobject معقد وفيه parameters واختيارات كتير، بستخدم Builder عشان أفصل عملية البناء وأخليها أوضح وكل خطوة مسمّاة. لو الـobject بسيط، الـconstructor العادي أفضل وأصدق.»
