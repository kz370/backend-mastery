Flyweight

لما يكون عندك عدد ضخم من الـobjects المتشابهة، تشارك الجزء الثابت بينهم بدل ما تكرّره في الذاكرة.

افتكرها

Flyweight = افصل الجزء المشترك (intrinsic) عن الجزء الخاص (extrinsic)، وشارك المشترك.

1المشكلة

تخيّل نظام بيعرض مليون منتج، وكل منتج فيه بيانات فئة مكرّرة:

class Product
{
    public function __construct(
        public string $name,           // مختلف لكل منتج
        public float  $price,          // مختلف لكل منتج
        public string $categoryName,   // مكرّر — «إلكترونيات» مليون مرة
        public string $categoryIcon,   // مكرّر
        public array  $categoryRules,  // مكرّر — array كبير
    ) {}
}

// مليون object، كل واحد شايل نسخة من بيانات الفئة
الحساب

لو بيانات الفئة 2 كيلوبايت، ومعانا مليون منتج في 50 فئة بس — يبقى إحنا بنكرّر نفس الـ2KB مليون مرة بدل 50 مرة. يعني 2 جيجا بدل 100 كيلو.

2الحل

// الجزء المشترك — Flyweight
final class Category
{
    public function __construct(
        public readonly string $name,
        public readonly string $icon,
        public readonly array  $rules,
    ) {}
}

class CategoryFactory
{
    private array $pool = [];

    public function get(string $name): Category
    {
        return $this->pool[$name] ??= new Category(
            $name,
            $this->loadIcon($name),
            $this->loadRules($name)
        );
    }
}

// الجزء الخاص — Context
class Product
{
    public function __construct(
        public string   $name,
        public float    $price,
        public Category $category,   // ← مرجع مشترك، مش نسخة
    ) {}
}
قبل: Product ×1,000,000 → كل واحد شايل نسخة من بيانات الفئة بعد: Product ×1,000,000 → مرجع → Category ×50 بس

3المصطلحات

المصطلحالمعنىالمثال
Intrinsic stateالجزء المشترك الثابت — بيتخزّن في الـFlyweightاسم الفئة وأيقونتها وقواعدها
Extrinsic stateالجزء الخاص بكل instance — بيتخزّن برهاسم المنتج وسعره
Flyweight Factoryبتضمن إن كل flyweight يتعمل مرة واحدة بسCategoryFactory
شرط أساسي

الـFlyweight لازم يكون immutable. لو أي كود قدر يعدّله، التعديل هيظهر في مليون منتج في نفس اللحظة — وده كابوس debugging.

4امتى تستخدمه

الـFlyweight حل لمشكلة أداء محددة، مش تحسين تصميم. استخدمه لما:

  • عندك عدد ضخم فعلًا من الـobjects (عشرات الآلاف+).
  • الذاكرة بقت مشكلة مقاسة — مش تخمين.
  • معظم البيانات مشتركة وقابلة للفصل.
ما تستخدموش قبل القياس

الـFlyweight بيزوّد التعقيد بشكل واضح (factory + فصل الحالة). في تطبيق ويب عادي بيعرض 20 منتج في الصفحة، ده over-engineering خالص. قِس الأول، وبعدين حسّن.

5في العالم الحقيقي

  • محررات النصوص: كل حرف object، لكن معلومات الخط والحجم مشتركة.
  • الألعاب: آلاف الأشجار، لكن الـmesh والـtexture مشتركين.
  • PHP internals: الـinterned strings — النص المتكرر بيتخزّن مرة واحدة.
  • ORMs: الـidentity map بتضمن إن الـrecord الواحد له object واحد في الـsession.

6Interview

Why Flyweight?

«لما يكون عندي عدد ضخم من الـobjects ومعظم بياناتهم مكرّرة، بفصل الجزء المشترك في object منفصل immutable، وكل instance بيشاور عليه بدل ما ياخد نسخة. لكن دي optimization لمشكلة ذاكرة مقاسة، مش شكل تصميم افتراضي — لأنها بتزوّد التعقيد بشكل ملحوظ.»
