افتكرها

Strategy = نفس العملية، طرق تنفيذ مختلفة — السؤال: إزاي أنفّذ؟

1المشكلة

عندنا عملية دفع واحدة، لكن طرق مختلفة: Credit Card، PayPal، Wallet. الحل المباشر:

class OrderService
{
    public function pay(string $method, float $amount)
    {
        if ($method === 'credit_card') {
            // Credit Card payment
        } elseif ($method === 'paypal') {
            // PayPal payment
        } elseif ($method === 'wallet') {
            // Wallet payment
        }
    }
}
المشكلة

الـOrderService بدأ يعرف تفاصيل كل طريقة دفع. ولو أضفنا طريقة جديدة، غالبًا هنضطر نعدّل OrderService — وهو مالوش دعوة أصلًا بإزاي Stripe بتشتغل.

وأخطر من كده: نفس التفرقة هتتكرر في refund() وgenerateReceipt() وcanRetry().

2الحل

interface PaymentStrategy
{
    public function pay(float $amount);
}

class CreditCardPayment implements PaymentStrategy
{
    public function pay(float $amount)
    {
        // Credit Card logic
    }
}

class PayPalPayment implements PaymentStrategy
{
    public function pay(float $amount)
    {
        // PayPal logic
    }
}

class WalletPayment implements PaymentStrategy
{
    public function pay(float $amount)
    {
        // Wallet logic
    }
}

class OrderService
{
    public function __construct(
        private PaymentStrategy $payment
    ) {}

    public function pay(float $amount)
    {
        $this->payment->pay($amount);
    }
}
Strategy ↓ نفس العملية ↓ طرق تنفيذ مختلفة

مثال آخر بنفس الشكل: حساب الشحن، وكل دولة ليها طريقة مختلفة لحساب التكلفة أو مدة التوصيل:

Shipping ↓ calculateShipping() ├── Egypt ├── US └── UK

3مهم — مش كل if تتحوّل لـStrategy

امتى الـif كفاية؟

لو عندك اختيارين والـlogic بسيط جدًا، ممكن الـif تكون كفاية وأوضح.

الـStrategy بتبقى مفيدة لما يكون عندك behaviors مختلفة لنفس العملية، والـbehaviors دي قابلة للتغيير أو الإضافة أو التبديل.

اسأل: هل الأنواع هتزيد؟ هل نفس التفرقة بتتكرر في أكتر من method؟ هل كل نوع فيه منطق حقيقي؟ لو الإجابة لأ على التلاتة، سيب الـif.

6Interview

Why Strategy instead of if/else?

«عندي نفس الـbehavior لكن أكتر من implementation، فبفصل كل implementation في Strategy مستقلة، والـclient يعتمد على abstraction واحدة. لو عندي اختيارين بسيطين والـlogic صغير، ممكن أستخدم if/else عادي. لكن لما الـbehaviors تبقى قابلة للإضافة أو التبديل، الـStrategy بتقلل الـcoupling وتخلي إضافة implementation جديدة ما تجبرنيش أعدّل الـservice الأساسي.»

الخلاصة

نفس العملية، لكن طرق تنفيذ مختلفة، فبفصل كل طريقة في Strategy مستقلة.
