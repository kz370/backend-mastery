Decorator

عندي object شغال كويس، وعايز أضيف له behavior جديد من غير ما أعدّل الـobject الأصلي.

افتكرها

Decorator = أضيف behavior للـobject من غير ما أعدّل الـobject الأصلي — بأني ألفّه.

1المشكلة

class ImageProcessor
{
    public function process(string $image): void
    {
        // resize image
    }
}

وبعدين عايز تضيف: Watermark، Encryption، Compression. والحاجات دي ممكن تتركّب مع بعض بأي شكل.

الحل الغلط: class لكل تركيبة
ImageProcessorWithWatermark ImageProcessorWithEncryption ImageProcessorWithCompression ImageProcessorWithWatermarkAndEncryption ImageProcessorWithWatermarkAndCompression ImageProcessorWithEncryptionAndCompression ImageProcessorWithAllThree ... 2^n classes

2الحل

interface ImageProcessorContract
{
    public function process(string $image): void;
}

class ImageProcessor implements ImageProcessorContract
{
    public function process(string $image): void
    {
        // resize
    }
}

class WatermarkDecorator implements ImageProcessorContract
{
    public function __construct(
        private ImageProcessorContract $processor    // ← بيلفّ واحد من نفس النوع
    ) {}

    public function process(string $image): void
    {
        // add watermark
        $this->processor->process($image);
    }
}

التركيب

$processor = new ImageProcessor();
$processor = new CompressionDecorator($processor);
$processor = new EncryptionDecorator($processor);
$processor = new WatermarkDecorator($processor);

$processor->process($image);
WatermarkDecorator ↓ EncryptionDecorator ↓ CompressionDecorator ↓ ImageProcessor ← الـobject الأصلي

لاحظ إن الـdecorator بيقدر يضيف سلوك قبل النداء، بعده، أو الاتنين — أو حتى يمنع النداء أصلًا.

ملاحظة عن الترتيب

ترتيب الـDecorators مش قاعدة ثابتة في الـPattern؛ الترتيب بيتحدد حسب الـworkflow والمتطلبات. المهم إن الـDecorators ممكن تتركّب فوق بعض.

3ليه ده مفيد؟

  • نضيف behavior من غير تعديل الـobject الأصلي (Open/Closed).
  • نقدر نركّب أكتر من behavior مع بعض بأي ترتيب.
  • مش محتاجين class جديدة لكل combination — n decorators بدل 2ⁿ classes.
  • التركيب ممكن يتحدد في وقت التشغيل حسب config أو حالة المستخدم.

4الشرط الأساسي

الـDecorator لازم ينفّذ نفس الـinterface

دي النقطة اللي بتفرق الـDecorator عن أي wrapper عادي. لأنه بينفّذ نفس الـinterface:

  • الـclient ما يعرفش إنه بيتعامل مع decorator أصلًا.
  • تقدر تلفّ decorator جوه decorator تاني.
  • تقدر تشيل decorator من غير ما تلمس أي كود تاني.

لو الـwrapper بيغيّر الـinterface، فده Adapter مش Decorator.

6Interview

What is the Decorator Pattern?

«عندي object شغّال وعايز أضيف عليه behavior جديد من غير ما أعدّل الـobject الأصلي. بعمل Decorator بينفّذ نفس الـinterface، وبيمسك الـobject الأصلي جواه، ويضيف السلوك قبل أو بعد ما يستدعيه. كده أقدر أركّب أكتر من behavior مع بعض من غير ما أعمل class لكل تركيبة.»

الخلاصة

عندي Object شغال وعايز أضيف عليه Behavior من غير ما أعدّله، فبلفّه بـDecorator.
