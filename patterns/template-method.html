Template Method

الأب بيحدد هيكل الخوارزمية وترتيب خطواتها، والأبناء بيملّوا الخطوات المتغيّرة.

افتكرها

Template Method = الترتيب ثابت في الأب، والخطوات المتغيّرة في الابن.

1المشكلة

عندك عمليات استيراد بيانات من مصادر مختلفة، والخطوات واحدة والترتيب واحد:

CSV Import: افتح الملف → اقرا → حوّل → تحقق → احفظ → اقفل XML Import: افتح الملف → اقرا → حوّل → تحقق → احفظ → اقفل API Import: اتصل → اقرا → حوّل → تحقق → احفظ → اقفل

اللي مختلف: القراءة والتحويل بس. الباقي واحد بالظبط — ولو نسخت الكود، أي تعديل في الترتيب هيتكرر في تلات أماكن.

2الحل

abstract class DataImporter
{
    // الـTemplate Method — final عشان محدش يغيّر الترتيب
    final public function import(string $source): ImportResult
    {
        $this->before();

        $raw       = $this->read($source);      // ← الابن بيحدد
        $records   = $this->transform($raw);    // ← الابن بيحدد
        $validated = $this->validate($records); // مشترك

        $this->save($validated);                // مشترك
        $this->after();

        return new ImportResult(count($validated));
    }

    abstract protected function read(string $source): string;
    abstract protected function transform(string $raw): array;

    // خطوات مشتركة
    protected function validate(array $records): array { /* ... */ }
    protected function save(array $records): void      { /* ... */ }

    // Hooks — اختيارية، الابن يعمل override لو حب
    protected function before(): void {}
    protected function after(): void  {}
}

class CsvImporter extends DataImporter
{
    protected function read(string $source): string
    {
        return file_get_contents($source);
    }

    protected function transform(string $raw): array
    {
        return array_map('str_getcsv', explode("\n", $raw));
    }
}
ليه <code>final</code>؟

عشان الابن ما يقدرش يغيّر ترتيب الخطوات — وده بالظبط اللي الـpattern بيحميه. لو الابن قدر يعمل override للـimport() نفسها، خلاص الضمانة راحت.

3Hooks — نقطة مهمة

الـhook هي method فاضية في الأب، الابن يقدر يعمل لها override لو حب:

Concrete stepفيها كود جاهزغالبًا ما يلمسهاش
Hookفاضية أو فيها defaultاختياري يعمل override

4Template Method vs Strategy

Template MethodStrategy
الآليةوراثة (inheritance)تركيب (composition)
الوقتبيتحدد وقت الكتابةممكن يتبدّل وقت التشغيل
اللي بيتغيّرخطوات جوه خوارزمية ثابتةالخوارزمية كلها
المرونةأقل — مقيّد بالوراثةأعلى

عمليًا: لو الـworkflow ثابت وعايز تضمن الترتيب → Template Method. لو الخوارزمية كلها بتتبدّل → Strategy.

5الخطر

الوراثة بتيجي بتكلفتها

الـTemplate Method بيعتمد على الوراثة، فبيرث كل مشاكلها:

  • الابن مربوط بتفاصيل الأب الداخلية (fragile base class).
  • مقدرش تبدّل السلوك في وقت التشغيل.
  • الابن يقدر يورّث من class واحدة بس.
  • لو الأب كبر وبقى فيه 10 hooks، بيبقى صعب تتبع اللي بيحصل فعلًا.

لو حسّيت بالمشاكل دي، فكّر في تحويل الخطوات المتغيّرة لـStrategies محقونة بدل subclasses.

6Interview

Why Template Method?

«لما يكون عندي خوارزمية ترتيب خطواتها ثابت، وخطوة أو اتنين بس بيختلفوا حسب النوع. بحط الترتيب في method في الأب وأخليها final عشان محدش يغيّره، والخطوات المتغيّرة تبقى abstract والابن ينفّذها. الفرق عن الـStrategy إن دي بالوراثة والترتيب مضمون، والـStrategy بالـcomposition وأمرن.»
