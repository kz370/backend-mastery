افتكرها

Proxy = واقف مكان الأصلي بنفس الشكل، لكن متحكم في الوصول له.

1الفكرة

interface ReportGenerator
{
    public function generate(int $userId): string;
}

class HeavyReportGenerator implements ReportGenerator
{
    public function generate(int $userId): string
    {
        // 30 ثانية من الحسابات
    }
}

class CachedReportProxy implements ReportGenerator
{
    public function __construct(
        private ReportGenerator $inner,
        private Cache $cache,
    ) {}

    public function generate(int $userId): string
    {
        return $this->cache->remember(
            "report.$userId",
            3600,
            fn () => $this->inner->generate($userId)
        );
    }
}

الـclient بينادي generate() عادي، ومش عارف إن فيه cache في النص.

2الأنواع الأربعة

النوعبيعمل إيهمثال
Virtual Proxyبيأجّل إنشاء الـobject التقيل لحد ما تحتاجه فعلًاLazy loading للعلاقات في الـORM
Protection Proxyبيتحقق من الصلاحيات قبل ما يمرّر النداءAdminOnlyServiceProxy
Remote Proxyبيمثّل object موجود على سيرفر تانيAPI client بيبان كأنه object محلي
Smart Proxyبيضيف تصرفات إضافية زي عدّ المراجع أو loggingCaching، Retry، Metrics

3مثال: Virtual Proxy (Lazy Loading)

class LazyUserProxy implements UserInterface
{
    private ?User $user = null;

    public function __construct(
        private int $id,
        private UserRepository $repo,
    ) {}

    private function load(): User
    {
        return $this->user ??= $this->repo->find($this->id);
    }

    public function name(): string
    {
        return $this->load()->name();     // بيتحمّل عند أول استخدام فعلي
    }
}

دي بالظبط اللي Doctrine و Eloquent بيعملوها في الـlazy loading — بتفضل عندك proxy لحد ما تلمس البيانات.

4Proxy vs Decorator

أصعب تفرقة في الـStructural patterns

الاتنين بيلفّوا object بنفس الـinterface. الفروق:

DecoratorProxy
الهدفيضيف سلوك جديديتحكم في الوصول للأصلي
مين بينشئ اللي بيتلفالـclient بيدّيه للـdecoratorالـProxy غالبًا بينشئه أو بيعرف إزاي يجيبه
التركيبمتوقّع تركّب كذا واحدغالبًا واحد
الوعي بالأصليالـclient عارف إنه بيزوّد حاجةالـclient مفروض ما يحسّش بحاجة

الخلاصة العملية: لو بتزوّد قدرة → Decorator. لو بتتحكم في الوصول (تأجيل، صلاحيات، cache) → Proxy. وفي أحيان كتير الفرق نية أكتر منه كود.

5امتى ما تستخدموش

  • لو الـobject رخيص الإنشاء، الـVirtual Proxy تعقيد بلا فايدة.
  • لو الصلاحيات موجودة في طبقة أعلى (middleware/policy)، ما تكررهاش في proxy.
  • الـProxy بيخفي التكلفة الحقيقية — ده مفيد وخطر في نفس الوقت (شوف مشكلة N+1 في الـORMs).

6Interview

Why Proxy?

«لما أحتاج أتحكم في الوصول لobject من غير ما الـclient يحس. بعمل proxy بنفس الـinterface، وهو اللي بيقرر امتى ينادي الأصلي — فأقدر أضيف lazy loading أو caching أو صلاحيات في مكان واحد. الفرق عن الـDecorator إن الـDecorator بيضيف سلوك، والـProxy بيتحكم في الوصول.»
