Bridge

افتكرها

Bridge = افصل الـabstraction عن الـimplementation عشان الاتنين يتغيّروا بشكل مستقل.

1المشكلة — انفجار الـclasses

عندك أنواع إشعارات، وكل نوع ممكن يتبعت بأكتر من قناة:

UrgentNotification × Email / SMS / Push NormalNotification × Email / SMS / Push MarketingNotification × Email / SMS / Push
// بالوراثة
class UrgentEmailNotification    extends Notification {}
class UrgentSmsNotification      extends Notification {}
class UrgentPushNotification     extends Notification {}
class NormalEmailNotification    extends Notification {}
class NormalSmsNotification      extends Notification {}
// ... 9 classes
الرياضيات ضدك

3 أنواع × 3 قنوات = 9 classes. ولو ضفت قناة رابعة (WhatsApp) تبقى 12. ولو ضفت نوع رابع تبقى 16. الزيادة ضربية مش جمعية.

2الحل

افصل البُعدين: نوع الإشعار في هرم، وقناة الإرسال في هرم تاني، ووصّلهم بـcomposition:

// الـImplementation (القناة)
interface Channel
{
    public function send(string $to, string $body): void;
}

class EmailChannel implements Channel { /* ... */ }
class SmsChannel   implements Channel { /* ... */ }
class PushChannel  implements Channel { /* ... */ }

// الـAbstraction (نوع الإشعار)
abstract class Notification
{
    public function __construct(
        protected Channel $channel      // ← الـBridge
    ) {}

    abstract public function notify(User $user): void;
}

class UrgentNotification extends Notification
{
    public function notify(User $user): void
    {
        $this->channel->send($user->contact(), '🚨 عاجل: ' . $this->body);
    }
}

// الاستخدام — أي تركيبة ممكنة
$n = new UrgentNotification(new SmsChannel());
Notification (abstraction) Channel (implementation) ├── Urgent ├── Email ├── Normal ←bridge→ ├── Sms └── Marketing └── Push 3 + 3 = 6 classes بدل 9

دلوقتي إضافة قناة = class واحدة. وإضافة نوع = class واحدة. الزيادة بقت جمعية.

3Bridge vs Strategy

الاتنين شكلهم واحد في الكود!

الفرق مش في الشكل، الفرق في النية:

عدد الهرمينهرم واحد للـstrategiesهرمين مستقلين
التغييرغالبًا بيتبدّل في وقت التشغيلغالبًا بيتحدد وقت الإنشاء
النيةسلوكية (Behavioral)هيكلية (Structural)

عمليًا: لو الـabstraction عندها هرم خاص بيها كمان، فأنت في Bridge. لو فيه class واحدة بس بتستقبل strategies مختلفة، فدي Strategy.

4امتى تستخدمه

  • لما تلاقي أسماء classes فيها كلمتين مركّبتين (UrgentEmailNotification) — دي علامة على بُعدين متشابكين.
  • لما تحب تبدّل الـimplementation في وقت التشغيل.
  • لما البُعدين بيتطوّروا بسرعات مختلفة أو بيشتغل عليهم فرق مختلفة.
علامة سريعة

لو عدد الـclasses عندك = عدد الأنواع × عدد الخيارات، فأنت محتاج Bridge.

5Interview

Why Bridge?

«لما يكون عندي بُعدين مستقلين بيتغيّروا — زي نوع الإشعار وقناة الإرسال — والوراثة بتخليني أعمل class لكل تركيبة، فالعدد بيزيد ضربيًا. الـBridge بتفصلهم لهرمين وتوصلهم بـcomposition، فإضافة أي حاجة في أي بُعد بتبقى class واحدة بس.»
