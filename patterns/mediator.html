Mediator

لما objects كتير تبقى بتتكلم مع بعضها مباشرة وتتحوّل لشبكة متشابكة — تحط وسيط واحد ينسّق بينهم.

افتكرها

Mediator = بدل ما كل واحد يعرف الكل، الكل يعرف الوسيط.

1المشكلة

من غير Mediator — كل واحد يعرف الكل: A ←→ B ↕ ╳ ↕ C ←→ D عدد العلاقات = n(n-1)/2
class ShippingField
{
    public function onChange(): void
    {
        $this->countryField->refresh();       // يعرف الـcountry
        $this->taxField->recalculate();       // يعرف الـtax
        $this->totalField->update();          // يعرف الـtotal
        $this->submitButton->enable();        // يعرف الـbutton
    }
}
المشكلة

كل component بقى عارف كل الباقيين. إضافة component جديدة معناها تعديل كل اللي قبلها. وإعادة استخدام أي واحدة لوحدها بقت مستحيلة لأنها بتجرّ الباقي معاها.

2الحل

مع Mediator: A B ↘ ↙ Mediator ↗ ↖ C D عدد العلاقات = n
interface FormMediator
{
    public function notify(Component $sender, string $event): void;
}

class CheckoutFormMediator implements FormMediator
{
    public function __construct(
        private CountryField  $country,
        private ShippingField $shipping,
        private TaxField      $tax,
        private TotalField    $total,
    ) {}

    public function notify(Component $sender, string $event): void
    {
        if ($sender === $this->country && $event === 'changed') {
            $this->shipping->reloadOptions($this->country->value());
            $this->tax->recalculate($this->country->value());
            $this->total->update();
        }

        if ($sender === $this->shipping && $event === 'changed') {
            $this->total->update();
        }
    }
}

class ShippingField extends Component
{
    public function onChange(): void
    {
        $this->mediator->notify($this, 'changed');   // بيعرف الوسيط بس
    }
}

دلوقتي كل component بيعرف الوسيط بس. ومنطق التنسيق كله في مكان واحد تقدر تقراه وتفهمه.

3Mediator vs Observer

MediatorObserver
الاتجاهمركزي — الوسيط بيعرف الكل وبينسّقلامركزي — الـobservers بيسجّلوا نفسهم
المنطقمنطق التنسيق جوه الوسيطكل observer عنده منطقه
المعرفةالوسيط عارف كل الأطرافالـsubject ما يعرفش الـobservers
الاستخدامتفاعل معقد بين أطراف معروفةإعلان عن حدث لأطراف مجهولة

باختصار: Observer بيقول «حصل كذا، اللي مهتم يتصرف». Mediator بيقول «حصل كذا، وأنا عارف بالظبط مين يعمل إيه».

4امتى ما تستخدموش

الوسيط ممكن يتحوّل لـGod Object

لو حطيت كل منطق النظام في وسيط واحد، هتلاقي class ضخمة عارفة كل حاجة — وده أسوأ من الشبكة اللي كنت هارب منها. الحل: وسيط لكل مجموعة مترابطة (فورم واحد، شاشة واحدة)، مش وسيط للتطبيق كله.

وكمان: لو عندك تلات components بيتكلموا مع بعض بشكل بسيط، التواصل المباشر أوضح.

5في العالم الحقيقي

  • UI forms معقدة — حقول بتأثر على بعضها (أشهر استخدام).
  • Chat rooms — الغرفة هي الوسيط بين المستخدمين (المثال الكلاسيكي).
  • Air traffic control — البرج هو الوسيط بين الطيارات.
  • Service layer — بينسّق بين repositories وservices متعددة (شكل مبسّط من الفكرة).

6Interview

Why Mediator?

«لما يكون عندي مجموعة objects بتتكلم مع بعضها مباشرة وعدد العلاقات بيكبر بشكل تربيعي، بحط وسيط كل واحد يعرفه بدل ما يعرف الباقيين. منطق التنسيق بيتجمّع في مكان واحد، وأقدر أضيف component جديدة من غير ما ألمس القدامى. بس لازم أخلي بالي إن الوسيط ما يتحولش لـGod Object.»
