Factory Method

الـparent يحدد الـworkflow، والـsubclass يحدد الـobject اللي هيتعمل.

افتكرها

Factory Method = أنشئ أنهي object؟ — والإجابة بتيجي من الـsubclass، مش من الـparent.

1المشكلة

class ReportService
{
    public function generate(string $format)
    {
        if ($format === 'pdf') {
            $report = new PdfReport();
        } elseif ($format === 'excel') {
            $report = new ExcelReport();
        } elseif ($format === 'csv') {
            $report = new CsvReport();
        }

        return $report->generate();
    }
}

الـReportService هنا مسؤول عن حاجتين:

  1. تنفيذ عملية الـreport (الـworkflow).
  2. تحديد وإنشاء الـobject المناسب.

والاتنين بيتغيّروا لأسباب مختلفة — دي إشارة SRP واضحة.

2الحل

abstract class ReportCreator
{
    // الـFactory Method — الـsubclass هو اللي بينفّذها
    abstract protected function createReport(): Report;

    // الـworkflow المشترك
    public function generate(): string
    {
        $report = $this->createReport();

        return $report->generate();
    }
}

class PdfReportCreator extends ReportCreator
{
    protected function createReport(): Report
    {
        return new PdfReport();
    }
}

class ExcelReportCreator extends ReportCreator
{
    protected function createReport(): Report
    {
        return new ExcelReport();
    }
}

رحلة التنفيذ

$creator = new PdfReportCreator() ↓ $creator->generate() ↓ ReportCreator::generate() ← الـworkflow في الأب ↓ $this->createReport() ↓ PdfReportCreator::createReport() ← القرار في الابن ↓ new PdfReport() ↓ PdfReport->generate()

من بره أنت بتنادي generate() بس. اللي بيتغيّر هو الـcreateReport() اللي بتتنادى من جوه.

3Factory عادية vs Factory Method

✕ Simple Factory
Client ↓ Factory ↓ الـFactory هي اللي تختار Object
✓ Factory Method
Client ↓ Creator (parent: workflow) ↓ createReport() ↑ الـsubclass هو اللي يحدد Object
الجملة المهمة

Factory العادية: الـFactory هي اللي تختار الـobject (غالبًا بـif أو map).

Factory Method: الـsubclass هو اللي يحدد الـobject، مع وجود workflow مشترك في الـparent.

ملحوظة: الـ«Simple Factory» مش من الـ23 GoF أصلًا — هي اصطلاح شائع بس.

4امتى تستخدمه وامتى لأ

استخدمه لماما تستخدموش لما
فيه workflow مشترك ثابت، والمتغيّر هو الـobject اللي بيتعملمفيش workflow مشترك أصلًا — ساعتها Simple Factory أبسط
الـsubclasses موجودة أصلًا لأسباب تانيةهتخلق hierarchy كامل عشان تختار object واحد
عايز تفتح الباب لأنواع جديدة من غير تعديل الأبنوع واحد ومش متوقع يزيد

5في Laravel

الفكرة موجودة في الـManager classes: SessionManager, CacheManager. الـcreateDriver() هي الـfactory method، والـdrivers المختلفة (redis, file, database) هي المنتجات.

6Interview

Why Factory Method?

«عندي workflow مشترك، لكن عملية إنشاء الـobject مختلفة. فبخلّي الـparent يحتوي على الـworkflow، والـsubclass يحدد الـobject من خلال الـfactory method. كده أقدر أضيف نوع جديد بـsubclass جديدة من غير ما أعدّل الـworkflow الأساسي.»
