Chain of Responsibility

الطلب بيمرّ على سلسلة من المعالجين بالترتيب، وكل واحد يقرر: أتعامل معاه، أمرّره، ولا أوقفه.

1المشكلة

public function handleRequest(Request $request)
{
    if (! $this->isAuthenticated($request)) {
        return response('Unauthorized', 401);
    }

    if ($this->isRateLimited($request)) {
        return response('Too many requests', 429);
    }

    if (! $this->hasPermission($request)) {
        return response('Forbidden', 403);
    }

    if (! $this->isValid($request)) {
        return response('Invalid', 422);
    }

    return $this->process($request);
}
المشكلة
  • كل الفحوصات ملزوقة في method واحدة — SRP مكسورة.
  • الترتيب ثابت ومربوط بالكود.
  • مقدرش أعيد استخدام فحص واحد في مكان تاني.
  • لو عايز أشيل فحص لطلب معيّن، محتاج flags وifات جوه الـif.

2الحل

abstract class Handler
{
    private ?Handler $next = null;

    public function setNext(Handler $next): Handler
    {
        $this->next = $next;
        return $next;                    // عشان الـchaining
    }

    public function handle(Request $request): Response
    {
        return $this->next
            ? $this->next->handle($request)
            : $this->process($request);
    }

    abstract protected function check(Request $request): ?Response;
}

class AuthHandler extends Handler
{
    public function handle(Request $request): Response
    {
        if (! $request->user()) {
            return new Response('Unauthorized', 401);    // وقف السلسلة
        }

        return parent::handle($request);                  // كمّل
    }
}

بناء السلسلة

$auth = new AuthHandler();
$auth->setNext(new RateLimitHandler())
     ->setNext(new PermissionHandler())
     ->setNext(new ValidationHandler());

$response = $auth->handle($request);
Request ↓ Auth → فشل؟ → 401 ↓ نجح RateLimit → فشل؟ → 429 ↓ نجح Permission → فشل؟ → 403 ↓ نجح Validation → فشل؟ → 422 ↓ نجح Process

3Laravel Middleware

الـmiddleware في Laravel هي أشهر تطبيق للفكرة دي:

class EnsureTokenIsValid
{
    public function handle(Request $request, Closure $next)
    {
        if ($request->input('token') !== 'secret') {
            return redirect('/home');      // وقف السلسلة
        }

        return $next($request);            // كمّل للمعالج التالي
    }
}

والترتيب بيتحدد في الـconfig مش في الكود — وده بالظبط المكسب: السلسلة قابلة لإعادة الترتيب من غير تعديل أي handler.

5امتى ما تستخدموش

التكلفة
  • لو الفحوصات تلاتة ثابتين مش هيتغيّروا، الـifات أوضح.
  • الـdebugging بيبقى أصعب — لازم تتبع السلسلة كلها.
  • مفيش ضمان إن حد هيتعامل مع الطلب — لازم يكون فيه fallback في الآخر.
  • ترتيب السلسلة بيبقى معرفة مهمة موجودة بره الـhandlers.

6Interview

Why Chain of Responsibility?

«لما يكون فيه أكتر من معالج ممكن يتعامل مع الطلب، وعايز أفصل كل واحد في class مستقلة وأقدر أعيد ترتيبهم أو أشيل واحد من غير ما ألمس الباقي. أشهر مثال هو الـmiddleware: كل واحدة بتقرر تكمّل ولا توقف، والترتيب بيتحدد في الـconfig مش في الكود.»
