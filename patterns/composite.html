Composite

لما يكون عندك هيكل شجري، وعايز تتعامل مع العنصر المفرد والمجموعة بنفس الطريقة بالظبط.

افتكرها

Composite = الجزء والكل ليهم نفس الـinterface، فالـclient ما يفرقش بينهم.

1المشكلة

عندك نظام ملفات: ملفات ومجلدات، والمجلد ممكن يحتوي ملفات ومجلدات تانية:

function calculateSize($item)
{
    if ($item instanceof File) {
        return $item->size;
    }

    if ($item instanceof Folder) {
        $total = 0;
        foreach ($item->children as $child) {
            $total += calculateSize($child);      // ← تكرار الشرط في كل مستوى
        }
        return $total;
    }
}
المشكلة

كل عملية جديدة (حساب الحجم، العدّ، البحث، الحذف) لازم تعيد نفس الـif instanceof ونفس منطق المرور على الشجرة. والـclient مضطر يعرف الفرق بين النوعين.

2الحل

interface FileSystemItem
{
    public function name(): string;
    public function size(): int;
}

// Leaf — العنصر المفرد
class File implements FileSystemItem
{
    public function __construct(
        private string $name,
        private int $size
    ) {}

    public function name(): string { return $this->name; }
    public function size(): int    { return $this->size; }
}

// Composite — الحاوية
class Folder implements FileSystemItem
{
    private array $children = [];

    public function __construct(private string $name) {}

    public function add(FileSystemItem $item): void
    {
        $this->children[] = $item;
    }

    public function name(): string { return $this->name; }

    public function size(): int
    {
        return array_sum(
            array_map(fn (FileSystemItem $c) => $c->size(), $this->children)
        );
    }
}

الاستخدام

$root = new Folder('project');
$root->add(new File('index.php', 1200));

$src = new Folder('src');
$src->add(new File('Order.php', 3400));
$src->add(new File('User.php', 2100));
$root->add($src);

echo $root->size();     // 6700 — الـclient ما فرقش بين ملف ومجلد
FileSystemItem (component) ├── File (leaf) → size() = القيمة └── Folder (composite) → size() = مجموع الأولاد └── فيه FileSystemItem تانيين

4التحدي المعروف

فين تحط <code>add()</code> و <code>remove()</code>؟

فيه اختيارين، ولكل واحد ثمن:

الاختيارالميزةالعيب
في الـComponent (الـinterface)شفافية كاملة — الـclient ما يفرقش خالصالـFile هيبقى عنده add() مالهاش معنى (كسر LSP)
في الـComposite بسأأمن — كل نوع عنده اللي يخصهالـclient محتاج يعرف النوع عشان يضيف

التوصية العملية: حطها في الـComposite بس. الشفافية الكاملة بتكلّفك methods كاذبة، والأمان أهم.

5Interview

Why Composite?

«لما يكون عندي هيكل شجري وعايز الـclient يتعامل مع العنصر المفرد والمجموعة بنفس الطريقة. بعمل interface مشترك، والـleaf بينفّذ العملية مباشرة، والـcomposite بينفّذها بإنه يجمّع نتايج أولاده. كده أي عملية جديدة ما تحتاجش instanceof ولا منطق مرور متكرر.»
