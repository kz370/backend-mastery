افتكرها

Facade = أخفي التعقيد وأدّي الـClient واجهة بسيطة.

1المشكلة

عملية Checkout محتاجة تنسيق بين أربع خدمات:

class OrderController
{
    public function store(Request $request)
    {
        $this->paymentService->charge($order);
        $this->inventoryService->reserve($order);
        $this->shippingService->createShipment($order);
        $this->notificationService->send($order);
    }
}
المشكلة
  • الـController عارف كل الخدمات وترتيب استدعائها.
  • أي تغيير في الـworkflow بيتكرر في كل مكان بيعمل checkout (web، API، admin panel).
  • الـController بقى شايل معرفة ملهاش علاقة بمسؤوليته (استقبال HTTP request).

2الحل

class CheckoutFacade
{
    public function __construct(
        private PaymentService      $payment,
        private InventoryService    $inventory,
        private ShippingService     $shipping,
        private NotificationService $notification,
    ) {}

    public function checkout(Order $order): void
    {
        $this->payment->charge($order);
        $this->inventory->reserve($order);
        $this->shipping->createShipment($order);
        $this->notification->send($order);
    }
}

// الـController بقى:
$this->checkoutFacade->checkout($order);
Controller ↓ CheckoutFacade ↓ ┌────────────┬───────────┬──────────┬──────────────┐ Payment Inventory Shipping Notification

3المهم تفهم إيه؟

  • الـServices الأصلية ما اختفتش — لسه موجودة وشغّالة.
  • الـFacade مش بتستبدل الـSubsystem؛ هي بتوفّر طريقة أسهل للتعامل معه.
  • لو حد محتاج تحكم أدق، لسه يقدر يستخدم الـServices مباشرة.
  • الـClient بيعرف الـFacade بدل ما يعرف كل التفاصيل الداخلية.
نقطة مهمة

الـFacade مش لازم تغطّي كل قدرات الـsubsystem. هي بتغطّي حالة الاستخدام الشائعة. لو حاولت تغطّي كل حاجة، هتلاقيها بقت معقدة زي الـsubsystem نفسه — وساعتها مفيش فايدة.

4Facade vs Adapter vs Service

الهدفالـinterface الجديد
Facadeتبسيط subsystem معقدأبسط من الأصلي، وبيغطّي حالة استخدام
Adapterالتوافق بين واجهتين مختلفتينمفروض عليك من الـclient
Service / Actionتنفيذ عملية بيزنسغالبًا method واحدة

الفرق بين Facade وService رفيع: الـFacade بتركّز على التنسيق والتبسيط، والـService ممكن يكون فيها business logic خاصة بيها. عمليًا الاتنين بيتداخلوا كتير، ومحدش هيحاسبك على الاسم.

5تحذير

الـFacade ممكن تتحول لـGod Object

لو كل عملية في المشروع بتعدّي من نفس الـFacade، هتلاقيها بقت class بـ40 method — وده أسوأ من التعقيد اللي كنت بتهرب منه. الحل: facade لكل حالة استخدام (CheckoutFacade, RefundFacade) مش facade واحدة للنظام كله.

«Facade» في Laravel حاجة تانية

Cache::get() وDB::table() في Laravel مش الـFacade Pattern — دي آلية static proxy بتوصل للـcontainer. الاسم متشابه بس، والفكرة مختلفة تمامًا.

6Interview

What is the Facade Pattern?

«عندي subsystem معقد فيه كذا service، وأنا مش عايز الـclient يتعامل مع كل التفاصيل دي. فبعمل Facade توفّر interface بسيطة، وهي من جوه بتنسّق التعامل مع الـcomponents المختلفة. الـservices الأصلية بتفضل موجودة — الـFacade بس بتقدّم طريق أسهل للحالة الشائعة.»

الخلاصة

عندي Subsystem معقد، فبعمل Facade توفّر Interface بسيطة وتخفي التفاصيل.
